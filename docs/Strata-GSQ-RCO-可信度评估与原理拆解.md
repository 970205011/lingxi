# Strata × GSQ-RCO × Qwen3.8-Flash-Next：可信度评估与原理拆解

> 整理日期：2026-10-19
> 目的：核实"Strata 是国家队、模型和推理引擎很好用"这一传言，拆解 GSQ-RCO 量化方法，评估可信度，给出可参考路径。

---

## 0. 先说结论

- **Strata 不是国家队**：是个人开发者 Niko1221（斯洛文尼亚，@coldniko）的开源推理引擎，MIT 协议，2026-09-24 首个 commit，一周迭代 30 个版本。
- **"IQ 量化"不是 Strata 做的**：是 **ISTA-DASLab**（奥地利科学技术研究所 IST Austria，Dan Alistarh 领衔——GPTQ 的发源地）的 GSQ-RCO 系列 GGUF。Strata 只是消费这些文件。
- **模型是阿里 Qwen 团队** 2026-08-26 发布的 Qwen3.8-Flash-Next（125B 总参 MoE，每 token 激活 6B，外加 51B n-gram 嵌入表 + 4B MTP 模块，原生 262K 上下文）。
- **整体靠谱**：方法全公开（论文+代码+审计工件）、第三方已复现验证。但"task-lossless"只在官方自选的三个基准上成立，3-bit 依旧有质量折扣；Strata 侧有单人项目风险和中文营销号夸大成分。

**一条链三个主体，全部对不上"国家队"**：奥地利学术实验室（量化）→ 阿里（模型）→ 斯洛文尼亚个人（引擎）。说"Strata 是国家队"的信息源不可靠。

## 1. 为什么靠谱（5 条依据）

### 1.1 出身硬：量化方法出自 GPTQ 发明实验室
ISTA-DASLab 是 IST Austria 的实验室，Dan Alistarh 领衔，是 GPTQ、SparseGPT 等经典量化方法的发源地（GPTQ 一作 Elias Frantar 现于 OpenAI）。该实验室长期在 LLM 量化方向有顶会级产出，不是蹭热点的新团队。

### 1.2 方法完全公开，可审计
- 两篇论文：GSQ（arXiv:2604.18556，2026-04-20）、RCO（arXiv:2605.00649，2026-05-01）
- 代码开源：`github.com/IST-DASLab/GSQ`、`github.com/IST-DASLab/RCO`，另有 gptq-gguf-toolkit
- 每个发布的 GGUF 附带**审计工件**：`rco-allocation.txt`（每个张量分到什么档位的完整记录）+ imatrix 文件（重要性矩阵，1000 chunks × 4096 tokens 校准数据）
- "敢把全部分配决策公开给你查"本身就是强可信信号——造假成本高。

### 1.3 第三方已独立复现，数据吻合
- WaveCut 将 Qwen3.8-27B-GSQ-RCO-IQ3_S 移植到 NInfer-v3 后独立测试：
  - WikiText-2 perplexity 实测 **7.071** vs 官方标称 **7.07**（吻合）
  - AIME 2025 / 2026 双满分（与官方一致）
  - GPQA-Diamond 88.38 vs 官方 89.39（差约 1 分，属 harness 差异范围内）
- llm-bench.io 社区实测：27B IQ3_S 在 3 种 GPU 上 9 次运行记录，质量均分 83.5/100，消费级显卡代码任务 top 2。

### 1.4 宣称克制且具体，不是营销话术
官方只宣称三个基准（AIME25、LiveCodeBench v6、GPQA-Diamond）"task-lossless"，并给出与 Unsloth UD 系列同档对比的具体分差（同体积下 AIME25 +10 分、GPQA +8.59 分、LCB +4.57 分）。具体数字 + 可下载验证 = 可信度高。对比之下中文门户网站（网易/搜狐）那些"日更 10% 性能""改写 AI 普惠史"是社区段子被营销号当真事写，不可信。

### 1.5 Strata 侧有多个独立实测交叉印证
- wiselychen（5090+64GB）：IQ3_S 41 笔真实 agent 请求，decode 中位数 106.8 tok/s，prefill 3-4K tok/s；expert 缓存命中率 93.4%
- A6000 社区基准（48GB VRAM / 125GB RAM / Strata 0.1.44.1）：decode ~108 tok/s，agent 会话缓存命中率 68.7%
- llama.cpp 生态直接支持 IQ 系 GGUF（PR 已合入），不依赖 Strata 也能跑

## 2. 风险与边界（必须知道的 4 条）

### 2.1 "task-lossless" 有边界
- 仅限 AIME25 / LCB v6 / GPQA-Diamond 三个基准。长上下文、多语言、agentic 行为、幻觉率等维度**未覆盖**。
- 第三方 291 题 MMLU-Pro 实测：IQ3_S 得 65.3%，比 Unsloth UD-Q6_K_XL（68.7%）低约 3 分。**3-bit 依旧有质量折扣**，只是在官方选的三个基准上恰好无损。
- 换评测 harness 分数差异极大（某去审查版本 GPQA 60.6% vs 官方 88.89%，作者自己说明差距来自 harness + 消融，非量化本身）。**跨来源比分必须先对齐协议**。

### 2.2 基准是官方自跑、自选协议
AIME25 用 generative xhigh harness 跑出满分，BF16 基线也是同协议。自报数据 + 自选协议是行业常态，不构成造假，但意味着"无损"声明是**在特定测量条件下的成立**，推广到所有任务需谨慎。

### 2.3 RCO 按任务损失分配 bit，存在对所选基准过拟合的可能
分配策略由 AIME/GPQA/LCB 的任务损失梯度驱动，理论上对这三个任务"特化"过。这是合理推测而非已证实缺陷——rco-allocation.txt 公开，有兴趣可以分析分配是否与这三类任务的敏感性相关。

### 2.4 Strata 是单人项目
- 一周 30 版：迭代快，但明天的版本可能改变今天的行为（实测者每版留备份）。
- 一次只处理一个请求（无并发），定位是"单人 agent 机"，不是团队共享服务。
- 只支持 ISTA-DASLab 的 GGUF，且重度依赖 Qwen3.8-Flash-Next 这一个模型。
- 中文媒体的性能数字不要照单全收，**一切以本机实测为准**。

## 3. GSQ 原理：单个张量怎么压得准

**问题**：传统量化（含 GPTQ）把权重就近取整到网格，一次定死；2-3 bit 下误差大。

**GSQ（Gumbel-Softmax Quantization）做法**：
1. 把"每个权重归入哪一档"的离散选择，用 Gumbel-Softmax 松弛成连续可微问题；
2. **联合学习**逐坐标网格分配 + 逐组缩放系数，训练中反复修正（而不是一次取整不回头）；
3. 关键设计：松弛层数与目标位宽对齐（3 bit → 8 层），优化空间大小刚好，问题可解；
4. 结果：2-3 bit 区间把标量量化拉到接近向量量化（AQLM/QTIP）的精度，同时保持标准 GGUF 标量格式，llama.cpp 无需改内核。

**与 GPTQ 的关系**：从 GPTQ 的解出发再往下训练，属于"GPTQ 后 refinement"。

## 4. RCO 原理：总预算内每个张量分几 bit

**问题**：混合精度量化（如 Unsloth UD）靠人工规则分配档位，粗糙。

**RCO（Riemannian Constrained Optimization）做法**：
1. 对每个张量 × 全部候选量化类型各跑一遍 GSQ，建候选数据库；
2. 把"总文件大小恰好等于预算"重构成 logit 空间上的**光滑黎曼流形**，用任务损失的梯度直接搜索每个张量的档位；
3. 精确满足体积预算，无约束超参；离散化用动态规划找可行解；
4. 产出标准 GGUF + 审计文件 rco-allocation.txt。

**一句话**：GSQ 解决"压得准"，RCO 解决"预算花在刀刃上"。

## 6. 你能怎么参考（按成本排序）

### Level 1：零成本——读审计工件
下载任一 IQ3_S 的 GGUF 页面附带的 `rco-allocation.txt` + imatrix 文件，直接看"哪些张量吃高 bit、哪些被压到 2 bit"。这是一份免费的量化敏感度教科书。我们本地已经下载了。

### Level 2：小成本——对比基准
在自家机器上跑同一组 prompt，对比 GSQ-RCO IQ3_S vs Unsloth 同档 UD vs BF16（如能放下），用 lm-eval-harness 或简单固定题目集。你自己的 V100 32G 数据比任何文章都可靠。

### Level 3：中成本——复现产线
拿小模型（如 Qwen3.8-4B）跑通"算 imatrix → GSQ 逐张量 → RCO 搜索 → 拼 GGUF"。注意 GSQ 需加载 BF16 模型做优化，27B 约需 56GB 显存或 CPU offload；125B+51B 表的 Flash-Next 个人机器跑不动完整流程，但小模型学方法足够。

### Level 4：改进空间（已知的格式边界）
- GGUF 格式下 MoE 只能按**层**分配精度，不能按单个专家分配——而 Flash-Next 每层有 512 个专家、每 token 只用 10 个，按专家分配理论上更优（FreeToken/arXiv 2608.16157 走的就是这条路）
- n-gram 查找表固定 IQ4_NL，不参与搜索
- MTP 草稿头的专项 fine-tune（社区 v1.1 head：离线 k1 +28.5pt，serve 仅 +6.3%——验证成本吃掉了收益，说明投机解码的优化空间在验证侧）

### 与你现有 V100 栈的关系
你目前在 V100-32G-PCIe 上跑 Qwen3.8-Flash-Next（NInfer 社区移植版，geoffwatts/ninfer-v100）。两条可并行的路：
1. **Strata 路线**：有信源称支持 Pascal 时代 P100/V100，32G 显存可缓存 2 万+ 专家，理论上远快于 12GB 卡——需本机实测验证（R720XD 内存建议 ≥128GB，Flash-Next 专家全量常驻 RAM 需 ~55-84GB）
2. **NInfer + GSQ-RCO GGUF 路线**：WaveCut 已证明 NInfer 格式可直接吃 GSQ-RCO 权重且精度保持（ppl 7.071 ≈ 官方 7.07），你的 V100 移植版同理可试

## 8. 量化后与原版（BF16）差异有多大——分维度量化

> 补充于 2026-10-19。差异不是均匀的，取决于比什么维度。

### 8.1 差异分布表（以 27B IQ3_S 为例，对比 BF16 原版）

| 维度 | 差异 | 依据 |
|---|---|---|
| 数学竞赛（AIME25） | **0 分**（100 = 100） | 官方数据，WaveCut 独立复现 2025/2026 双满分 |
| 竞赛代码（LCB v6） | **0 分**（85.71 = 85.71） | 官方数据 |
| 科学推理（GPQA-D） | **-0.51 分**（89.39 vs 89.90） | 第三方独立测 88.38，差约 1.5 分，在 harness 噪声范围内 |
| 困惑度（WikiText-2） | 约 +0.0x（实测 7.071） | WaveCut NInfer-v3 独立实测 |
| 知识广度（MMLU-Pro） | 约 -1~-3 分 | 291 题实测 65.3%，比 6-bit UD-Q6_K_XL（68.7%）低 3 分；BF16 基线未直接测，方向为小幅损失 |
| **2.75 bit 以下（IQ2_XS/IQ2_XXS）** | **悬崖** | 2-bit 档能力保留约 82.5%（juejin 实测），代码任务明显掉；独立基准确认 4-bit 以上无感、2-bit 开始崩（quesma 实测：Q4_K_M 与 BF16 持平，UD-Q2_K_XL "breaks a bit"） |

**规律**：3 bit 及以上，差异集中在知识广度类任务（小个位数分差）；数学/代码/科学推理三类任务在测量噪声级（±0.5 分内）。2.75 bit 是悬崖线。

### 8.2 两个必须知道的边界

**1. "无损"是任务级，不是逐位级。**
官方原话是 task-lossless，不是 bit-exact。量化后逐 token 输出会漂移：同一道题采样两次可能给不同推理路径，只是答案分布的统计分数持平。用于需要输出稳定可复现的场景（生成测试数据、diff 对比）时能感觉到差异。

**2. 长上下文和非英语是未验证盲区。**
学术研究（arXiv:2505.20276，9.7K 样本、5 种量化方法）结论：4-bit 量化在长输入任务上损失最高可达 59%，且**非英语语言敏感度是英语的 5 倍**。GSQ-RCO 所有"无损"声明都发生在英文、短中上下文基准上——**中文场景差异大小无任何公开数据**，是未知区而非"已证明无损"。

### 8.3 容易忽略的一环：KV cache 量化

实测者明确指出：**KV cache 量化的降智比权重量化还狠**。"和原版差多少"不只由权重文件决定，还由推理时 KV cache 精度决定——f16 KV 与 q4 KV 的差异可能比 IQ3_S 和 BF16 的差异还大。对比实验时应固定 KV cache 设置，否则权重差异会被 KV 差异淹没。

### 8.4 一句话结论

跑数学/代码/agent 任务（英文为主）：与原版差异在测量噪声级，放心用。跑中文长文任务：无公开数据背书，应自行用固定题目集做回归对比（V100 上 20 分钟可完成验证）。
