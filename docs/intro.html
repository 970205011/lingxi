为什么会有 lingxi

HARDWARE

V100 被主流栈留在 sm_80 门外

没有 bf16 张量核、没有 FP4；int4 dp4a 在 Volta 上跑不过 4 路 FP32 FMA。 vLLM / TRT-LLM / FlashInfer / DeepGEMM 的底线都已是 sm_80。

MODEL

Qwen3-Next 不是上一代架构

GDN 线性递推 + 每 4 层一次稀疏全注意力 + 512 专家 MoE + 95 GiB 外置 PLE 表 + 自带 MTP 头。llama.cpp 支持仍在完善；strata 能跑，但不是 V100 专用调优。

ECONOMICS

专家权重是生死线

24,576 个专家，Q4G64 全量 59.8 GiB；每 token 触达 480 个专家（1.25 GB）。 没有驻留与搬运体系，decode 会被 PCIe 拖死。

我们做了什么

EXPERTS

Q4G64 arena + LRU 槽 + 钉表

热专家离线按真实流量钉进显存，在线重钉；整段锁页把 p50 从 8.8 提到 34.3 tok/s。

MIX

逐槽混档 + GPTQ 备选

热 Q4 / 冷 Q3，arena 60.3 → 46.4 GiB（−23%），端到端计时与全 Q4 打平。

MTP

概率闸门 + 重放两刀

min_p=0.7 停链、砍 head 重放、prob1 廉价近似；17.0 → 约 64 tok/s，输出逐 token 不变。

LONG CTX

注意力三刀 + PLE 进内存

稀疏注意力只 gather 选中块；QSA 选块 O(n) 基数选择；FP8 PLE 表进 /dev/shm。

SERVE

前缀缓存 + 并发会话

精确 / 智能两档；多轮第二轮 28.1s → 0.35s（81×），原样重发 0.16s（177×）。

VERIFY

T1 / T2 / T3 + 4 gates

每 kernel 对 torch、逐层 golden、端到端贪心逐位；任何重构 gates 全绿才合入。

全专家上卡是可能的。 GPU1 已经全驻留；GPU0 只差 865 个冷专家（1.58 GiB）。 把 32K KV 放 host 省 0.43 GiB，再把预留/边距收紧约 1.2 GiB，或把一部分热 Q4 降为 Q3， GPU0 也能全驻留。旧 autotune 按 Q4 blob 估算所有槽，少算了约 2,000–2,500 槽/卡； 现在按每个 blob 的真实 Q4/Q3 格式算。

KV 为什么不必一直全在显存

LINGXI_QSA_PAGED=1 已经实现了块表 + host 锁页块池 + LRU 下沉/预取： 设备只保留 LINGXI_QSA_WIN_TOKENS（默认 32K）的常驻窗口，其余 KV 在 host。 短上下文时 KV 本来只有 0.43 GiB/卡，省不出多少；256K 时逻辑 KV 是 3.5 GiB/卡， paging 能省约 3.1 GiB/卡，正好补专家槽。

上下文逻辑 KV / 卡设备常驻窗口省下的显存
32K0.43 GiB0.43 GiB（全量）0
256K3.5 GiB0.43 GiB（32K 窗口）≈3.1 GiB
代价不是零：稀疏注意力每个 token 仍要从 host 取选中的 KV 块，需要预取/重叠。 strata 的 --kv-resident 32768 是同一思路，长上下文实测速度基本不降； 前提是块池在锁页内存、预取能盖住 PCIe。

和 strata 的真实差距

口径strata 0.2.2（本机实测）lingxi
decode（短 / 4K / 14K）86–110 tok/s（2×V100, IQ3_XXS, MTP）43（无 MTP）/ 约 64（MTP）
prefill（4K / 14K）6.0 s / 13.5 s（约 690 / 1,080 tok/s）4.2K 28.7 s；33K 278.7 s（约 118 tok/s）
量化IQ3_XXS（约 3-bit，47 GB）Q4 / Q3 混档（46.4 GiB）
专家驻留双卡 100%GPU1 100%，GPU0 95%（差 865 个冷专家）
KVint8 + 32K 常驻窗口paged KV 已实现，默认关

结论：decode 差距约 1.5–2×，但 prefill 差约 6–10×。strata 的 prompt 路径用 FP16 张量核做 attention（本地复测 int8 KV、32K、2048 queries：FP32 25.7 ms → 张量核 12.5 ms， 2.06×）和 grouped expert GEMM；它的 IQ3_XXS 也让专家 100% 驻留。lingxi 下一版的第一优先级 就是 prefill 张量核，而不是继续在 32G 上抠 decode 的几个毫秒。

协议：temperature 0、max_tokens 128、流式；strata 的 reasoning_content 计入输出； 两引擎量化不同，不是 bit 级横比。

补充：用 Strata 文档里的 v2 生产参数（SM70_TABLE、spec-min-p 0.80、mtp-hnorm stream 等） 复跑，4K/14K 冷 prefill 可压到 3.6 s / 8.3 s，decode 64–92；200 tok/s 峰值在本机未复现。

快速开始

make build
./start.sh
./start.sh ./bin/lingxi-bench serve <产物.lingxi 或 .ninfer> 11434

# 只看显存账，不加载权重
./bin/lingxi-bench vram-budget <artifact> <arena> 24 32768

curl http://127.0.0.1:11434/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"lingxi","messages":[{"role":"user","content":"The capital of France is"}]}'

产物约 253 GB，不入库；从 HF checkpoint 重建见 tools/convert/hf2lingxi.py。 运行参数全部是环境变量，登记在 crates/lingxi-model/src/probes.rs。
